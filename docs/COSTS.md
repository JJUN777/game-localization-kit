# LLM 사용량과 비용

이 문서는 GLK에서 AI API 호출이 발생하는 단계, 비용 계산 방법과 실제 프로젝트 기준 예시를 정리합니다.

**대상 독자**: 프로젝트를 시작하기 전 비용을 예측하거나, 비용을 줄이고 싶은 모든 사용자

---

## 한눈에 보는 비용

> 아래 금액 기준: `gemini-2.5-flash`, 1달러 = 1,550원, Gemini 무료 할당량 미적용, 정상 1회 처리
>
> **Gemini 무료 티어 범위 안에서는 비용이 발생하지 않습니다.** 현재 프로젝트의 실제 한도는 [Google AI Studio](https://aistudio.google.com/)에서 확인합니다. 무료 한도는 모델과 계정에 따라 다를 수 있으므로 [공식 Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)도 참고합니다.
>
> 아래 금액과 실측 예시는 Gemini 전용입니다. OpenAI를 선택한 경우 모델별
> 입력·출력 단가가 다르므로 [OpenAI API 가격 안내](https://developers.openai.com/api/docs/pricing)에서 현재 단가를 확인하세요.

### 룰북 PDF (페이지당)

```text
영어 원문 약 1,000~1,500자 기준

PDF 읽기 순서 복원: 약 10~20원
초벌 한국어 번역:   약  5~15원
────────────────────────────
합계:               약 15~35원/페이지
```

| 룰북 분량 | 참고 총액 |
|---:|---:|
| 1페이지 | 약 15~35원 |
| 10페이지 | 약 150~350원 |
| 50페이지 | 약 750~1,750원 |
| 100페이지 | 약 1,500~3,500원 |

### 이미지 OCR (장당)

```text
thinking 제외 실측: 약 3원
동적 thinking 포함 예산: 약 3~15원
```

| 이미지 수 | thinking 제외 | thinking 포함 예산 |
|---:|---:|---:|
| 5장 | 약 15원 | 약 15~75원 |
| 100장 | 약 300원 | 약 300~1,500원 |
| 1,000장 | 약 3,000원 | 약 3,000~15,000원 |

### 비용이 없는 작업

원문 QA, 용어 후보 생성, termbase import, 번역 QA, 검수 화면의 일반적인
조회·편집·저장·최종 승인, 프로젝트 목록과 상태 확인은 모두 로컬 처리이므로
API 비용이 없습니다. 단, PDF 원문 검수 화면에서 사용자가 명시적으로 실행하는
`선택 블록 AI 검사`는 선택한 block마다 이미지 입력을 포함한 API 요청 한 번이
발생합니다. 동일한 입력과 설정으로 이미 검사한 block은 로컬 저장 결과를
재사용하므로 추가 비용이 발생하지 않습니다.

## 비용이 발생하는 단계

| 작업 | LLM 호출 | 호출 단위 |
|---|---:|---|
| `glk init`, `glk projects`, `glk status` | 없음 | 로컬 처리 |
| PDF 텍스트·좌표 추출과 페이지 렌더링 | 없음 | 로컬 처리 |
| PDF 읽기 순서 복원 | 있음 | 캐시되지 않은 PDF 페이지마다 1회 |
| 이미지 OCR | 있음 | 캐시되지 않은 이미지마다 1회 |
| `segment`, 원문 QA와 원문 검수 | 없음 | 로컬 처리 |
| 용어 후보 생성과 termbase import | 없음 | 로컬 처리 |
| 초벌 번역 | 있음 | 캐시되지 않은 번역 chunk마다 1회 |
| 번역 검수·QA·최종 승인 | 없음 | 로컬 처리 |
| QA 오류 block 선택 재번역 | 있음 | 재번역 대상 block마다 1회 |

번역 프롬프트 저장·수정 자체는 API를 호출하지 않습니다. 프롬프트 변경 후
전체 재번역을 선택하면 기존 청크를 재사용하지 않으므로 모든 번역 chunk에
비용이 다시 발생합니다.

`--dry-run`은 입력과 실행 가능 여부만 확인하며 AI API를 호출하지 않습니다.

## 계산식

```text
입력 비용 = 입력 token ÷ 1,000,000 × 입력 단가
출력 비용 = (표시 출력 token + thinking token) ÷ 1,000,000 × 출력 단가
총비용 = 입력 비용 + 출력 비용
```

이미지도 token으로 환산됩니다. Google은 큰 이미지를 768×768 tile로 나누고 tile마다 token을 계산합니다. 정확한 입력량은 API의 `count_tokens`로, 실제 청구 대상은 응답의 usage metadata로 확인할 수 있습니다.

참고 링크:
- [Token 계산과 count_tokens](https://ai.google.dev/gemini-api/docs/tokens)
- [Gemini API 결제 안내](https://ai.google.dev/gemini-api/docs/billing/)

## 실측 예시: PDF 읽기 순서 복원

PDF 룰북 측정 샘플의 렌더 이미지(787×1187px)와 실제 prompt를 `count_tokens`로 측정하고, 저장된 JSON 출력을 같은 tokenizer로 계산한 결과입니다.

| 페이지 | fragment 수 | 입력 token | 출력 추정 token | thinking 제외 비용 |
|---|---:|---:|---:|---:|
| 1 | 57 | 3,479 | 1,364 | 약 $0.0045 (≈7원) |
| 2 | 108 | 5,870 | 1,974 | 약 $0.0067 (≈10원) |

동적 thinking을 포함하면 페이지당 약 10~20원 범위가 됩니다. thinking token 1,000개마다 약 $0.0025(≈4원)가 추가됩니다.

## 실측 예시: 이미지 OCR

이미지 OCR 측정 샘플의 카드 이미지 5장(모두 932×1270px)과 아이콘 30종 상세 prompt를 `count_tokens`로 측정한 결과입니다.

| 항목 | 값 |
|---|---:|
| prompt token | 2,716 |
| 이미지 token | 259 |
| 장당 전체 입력 token | 2,974 |
| 기존 OCR 출력 token | 평균 394 (최소 341, 최대 445) |

| 구분 | 입력 비용 | 출력 비용 | 합계 | 원화 |
|---|---:|---:|---:|---:|
| 출력 최소 (341) | $0.000892 | $0.000853 | $0.001745 | 약 2.7원 |
| 출력 평균 (394) | $0.000892 | $0.000985 | $0.001877 | 약 2.9원 |
| 출력 최대 (445) | $0.000892 | $0.001113 | $0.002005 | 약 3.1원 |

현재 OCR은 `thinking_budget`을 지정하지 않아 동적 thinking을 사용합니다. thinking token도 출력 단가로 과금됩니다.

| 장당 thinking 가정 | 장당 합계 | 원화 |
|---:|---:|---:|
| 0 token | 약 $0.0019 | 약 2.9원 |
| 1,000 token | 약 $0.0044 | 약 6.8원 |
| 3,000 token | 약 $0.0094 | 약 14.5원 |

실사용 예산은 장당 약 3~15원으로 잡는 것을 권장합니다.

## 실측 예시: 초벌 번역

PDF 룰북 측정 샘플의 확정 원문과 termbase로 실제 번역 prompt를 만들고 `count_tokens`를 호출한 결과입니다. 번역 생성 API는 호출하지 않았습니다.

| 항목 | 값 |
|---|---:|
| 승인 원문 block | 61개 |
| 원문 문자 | 2,742자 |
| 번역 chunk | 1개 |
| 활성 termbase | 3개 (approved 2, keep 1) |
| prompt 입력 token | 4,261 |
| 출력 비교용 source JSON token | 2,426 |

| 가정 | 입력 | 출력·thinking | 합계 | 원화 |
|---|---:|---:|---:|---:|
| thinking 없음 | $0.0013 | $0.0061 | 약 $0.0073 | 약 11원 |
| thinking 1,000 | $0.0013 | $0.0086 | 약 $0.0098 | 약 15원 |
| thinking 3,000 | $0.0013 | $0.0136 | 약 $0.0148 | 약 23원 |

번역 prompt에는 고정 규칙과 용어가 chunk마다 반복되므로, 원문 token만으로 비용을 계산하면 실제보다 작게 나옵니다.

## 재시도와 실패 비용

API는 성공 여부와 관계없이 사용한 token을 과금합니다. GLK에서 추가 요청이 발생하는 경우:

| 상황 | 최대 재시도 | 비용 영향 |
|---|---:|---|
| PDF fragment 집합 검증 실패 | 해당 페이지 최대 2회 재시도 (총 3회) | 최대 3배 |
| 번역 응답 검증 실패 (숫자·token·용어) | 최대 1회 재시도 (총 2회) | 최대 2배 |
| 선택 재번역 (`glk retry --failed`) | block마다 새 요청 | 추가 비용 |

PDF 페이지가 세 번 모두 실패해 partial 상태가 되더라도 사용한 token은 되돌아오지 않습니다.

## 캐시가 비용을 줄이는 방식

같은 원본, 모델과 prompt 설정으로 다시 실행하면 검증된 캐시를 재사용하므로 새 API 비용이 발생하지 않습니다.

```text
Page 2: reused validated layout cache
```

캐시를 무효화하는 변경:

- 원본 PDF 또는 이미지 변경
- 모델 변경
- OCR·번역 prompt 변경
- 처리 규칙이나 prompt version 변경
- `--force` 강제 재생성

사람이 수정하는 `review.txt`, 로컬 QA, HTML 검수 화면 자체는 AI API를
호출하지 않습니다. 명시적으로 재번역을 실행할 때만 비용이 추가됩니다.

---

## 예산을 아끼는 방법

1. **`--dry-run`으로 먼저 확인**: 입력 수와 chunk 계획을 API 없이 봅니다.
2. **`--force`를 쓰지 않기**: 정상 캐시가 있으면 재사용됩니다.
3. **실패 원인 먼저 파악**: PDF 전체를 다시 돌리기 전에 실패 페이지를 확인합니다.
4. **termbase를 확정한 뒤 번역**: 용어를 바꾸면 번역이 stale이 됩니다.
5. **샘플로 품질 확인**: 대량 작업 전에 몇 페이지·이미지로 시험합니다.
6. **직접 수정 vs 재번역 판단**: QA 오류를 사람이 고치면 API 비용이 없습니다.

## 대시보드 사용량 기록

대시보드에서 실행한 PDF·이미지 원문 준비, 초벌 번역과 검수 화면의 오류 문장
재번역은 AI 응답의 usage metadata를 작업 상태 또는 재번역 이력 JSON에
저장합니다. 작업 카드와 재번역 상태 패널에서 다음 값을 확인할 수 있습니다.

PDF 아이콘 검사는 결과 창에 해당 실행의 token과 예상 비용을 표시하고,
실제 API를 호출한 block별 사용량을 프로젝트의 `.glk/state/ai_usage.jsonl`에
`source_review` 단계 이벤트로 누적합니다. 저장된 검사 결과를 재사용한 경우에는
API 요청과 비용 이벤트가 추가되지 않습니다. 대시보드 프로젝트 카드의
단계별 비용표의 `원문 검수`에서 요청 수와 누적 예상 비용을 확인할 수 있습니다.
대시보드 원문 준비와 초벌 번역, 검수 화면의 오류 문장 재번역도 각각
`원문 추출`, `번역`, `번역 검수` 단계로 같은 원장에 누적됩니다.

- 실제 API 요청 횟수(검증 실패나 전송 재시도 포함)
- 입력·출력 token과 그중 thinking·cached input token
- 모델별 표준 유료 단가로 계산한 예상 USD 비용

금액은 세금, 환율, 무료 할당량, Batch·Flex·Priority·프로모션이나 계정별
할인을 반영하지 않은 참고치입니다. 단가표에 없는 사용자 지정 모델은 token만
기록하고 금액은 `단가 미등록`으로 표시합니다. 실제 청구액은 각 제공자 결제
대시보드에서 확인해야 합니다.

프로젝트 카드에는 `원문 추출`, `원문 검수`, `용어 정리`, `번역`, `번역 검수`
비용과 전체 누적 AI 비용을 표시합니다. 로컬 처리만 하는 용어 정리와 일반적인
사람 검수는 `$0`이며, 원장 도입 전에 실행돼 usage metadata가 남지 않은 작업은
`기록 없음`으로 표시합니다.
