# 후속 작업 백로그

이 문서는 현재 안정화 범위가 끝난 뒤 다시 우선순위를 정할 작업을 보관합니다.
`ERROR-003`, `ARCH-006`, `DOMAIN-001`을 포함한 안정화 작업의 완료 기록은
[`IMPROVEMENTS.md`](IMPROVEMENTS.md)에서 관리합니다.

백로그 항목은 구현 순서를 뜻하지 않습니다. 제품 흐름, 실제 사용 빈도와 작업
비용을 확인하고 진행 여부와 순서를 결정합니다.
작업을 시작할 때는 해당 항목을 `IMPROVEMENTS.md`로 옮기고 완료 기준과 회귀
테스트를 구체화합니다.

## 제품 기능

### `FEATURE-001` AI 설정 연결 테스트

- 실제 Gemini 최소 호출로 API 키·모델·권한·사용량 한도를 구분해 진단합니다.
- 호출 전에 비용이 발생할 수 있음을 명확히 안내합니다.
- 로컬 형식 검사와 실제 API 연결 검사를 별도 동작으로 구분합니다.

### `FEATURE-002` 원문 검수 선택 영역 OCR 재인식

- PDF·이미지의 선택 영역을 다시 OCR하고 해당 검수 블록 입력창을 자동으로
  채우는 흐름을 검토합니다.
- 기존 블록을 바로 덮어쓰지 않고 사용자가 결과를 확인한 뒤 적용하게 합니다.

### `FEATURE-003` 프로젝트 내보내기·가져오기

- 다른 PC로 이동할 때 필요한 프로젝트 파일, 사용자 설정과 제외할 cache 범위를
  먼저 결정합니다.
- 기존 프로젝트 충돌, 경로 차이, schema version과 가져오기 실패 복구 방식을
  포함해 설계한 뒤 구현합니다.

## 실측 또는 정책 결정 뒤 진행

### `UPLOAD-001` 대용량 multipart 업로드 스트리밍

- 현재 상한인 256 MiB 본문을 메모리에 모두 올리는 방식의 실제 사용량을
  측정합니다.
- 일반적으로 등록하는 PDF·이미지 크기와 최대 메모리 사용량을 확인한 뒤
  스트리밍 파서 도입 여부를 결정합니다.

### `REPO-002` 저장소 라이선스

- 현재는 LICENSE를 추가하지 않습니다.
- 배포·공개 범위, 라이선스 종류와 저작권자 표기를 결정한 뒤 다시 진행합니다.
